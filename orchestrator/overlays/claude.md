## Claude Code

- You start subagents with the tool `Agent`, the role as `subagent_type`. The role brings its model and effort; `model` and `effort` per call only when the user says so. The `description` of an `Agent` call for a plan task starts with the task id and a space (`A1 write interface`), so the herdr card links the subagent to the task.
- All five roles are there: `planner` and `reviewer` (read-only, no shell, no web) and `researcher` (read-only, with web) next to `implementer` and `tester`. Implementer, tester and researcher may run on non-Claude models in OpenCode; here they are Claude models.
- **Planning:** for a larger or unclear task the `planner` drafts the plan; you put it into the format and check it. Small tasks you plan yourself.
- **Reviewing:** the `reviewer` cannot produce the diff itself: put it into its brief (`git diff`, or the changed files with their base), together with the task's goal and its musts. Check strictly: a finding with file, line and case goes back as a redo, style questions without consequences do not. You still run the proof yourself.
- **Parallel:** start the independent tasks of a phase in one message with several `Agent` calls. Readers need nothing more.
- **Parallel writers in worktrees:** a writing task that runs at the same time as another writing task gets `isolation: "worktree"` in its `Agent` call. Rules:
  - Only from a clean working tree (`git status` empty): a worktree starts from a commit and does not see uncommitted changes. Takeovers are commits (base.md, Limits), so the tree is clean again after each, and a task that waits for another starts after that one is taken over. Put the base commit (`git rev-parse HEAD`) into the brief.
  - The brief tells the worker to check first that `git rev-parse HEAD` in its worktree is that base commit, and otherwise to stop with `STATUS: blocked`; Claude Code may start worktrees from the remote default branch (setting `worktree.baseRef`). Blocked: run that lane after the others in the working tree instead.
  - The brief asks the worker to commit its work on the worktree's branch and to name the branch in its report.
  - On takeover publish the branch: `nc orchestrator status task <id> pass branch=<worktree branch> …`.
  - Take each branch over after your check with `git cherry-pick` as a commit (base.md, Limits), one at a time in plan order, running the task's proof after each. On a conflict: `git cherry-pick --abort` (earlier takeovers stay as commits), confirm with `git status` that nothing is in progress, and report the task as conflicted; never copy files over from the branch. Remove the worktree and the branch (`git worktree remove`, `git branch -D`) only after step 7, once the whole suite has passed.
  - Not inside a task container: there the work is isolated already; write in one lane.
- **Redo:** a finished subagent keeps its context. Send the finding to the same worker with `SendMessage` (its agent ID or name) instead of starting a new one with a new brief.
- **`nc delegate`** (server only): start with `--bg`, then `nc delegate --result <id> --wait` with `run_in_background` (skill `delegate`). `nc delegate --list` finds earlier runs again, for example after a compaction. Publish the run with `nc orchestrator status task <id> running delegate=<delegate task id>`. Its brief leaves out the no-commit limit and the `Report` line: the worker contract makes it commit and fixes the first line of `RESULT.md`.
